# 해시 보충 — 빈도, 존재 확인, 그룹 집계

## 편성 이유와 근거 (2026-10-14)

현대모비스 해시 출제 빈도가 낮다는 근거는 확인하지 못했다. 확인한 [2026년 하반기 공식 SW 채용 공고](https://careers.mobis.com/jobs-view?seq=4168)는 코딩테스트 전형을 안내하지만 유형별 비율을 제공하지 않는다. 직무·시기가 다른 개인 후기를 전체 출제 통계로 일반화하지 않는다. 이 보충은 기출 빈도 예측이 아니라 기존 Day 2에서 부족했던 해시 활용 연습을 채우기 위한 것이다.

[프로그래머스 해시 학습 목록](https://school.programmers.co.kr/learn/courses/30/parts/12077)의 문제로 구성했다. 현대모비스 기출이라는 의미는 아니다.

Day 13 이후, Day 14 미니 테스트 전에 1·2번을 푼다. Day 15 약점 시간에는 3번을 선택해 해시와 정렬을 함께 연습한다. 기존 날짜 폴더와 풀이는 유지한다.

## 먼저 알아둘 개념

| 용도 | 자료구조 | 삽입·조회·삭제 |
|---|---|---|
| 키별 개수나 값 저장 | unordered_map | 평균 O(1), 최악 O(N) |
| 존재 여부와 중복 제거 | unordered_set | 평균 O(1), 최악 O(N) |
| 키 정렬 및 범위 탐색 | map / set | O(log N) |

해시는 키를 해시값으로 변환해 저장 위치를 찾는 방식이다. 충돌이 발생할 수 있으며 평균 상수 시간이지 항상 상수 시간은 아니다.

```cpp
unordered_map<string, int> freq;
freq["apple"]++; // 없으면 0으로 생성한 뒤 증가
if (freq.find("pear") != freq.end()) {
    // 키가 존재함. 조회만 할 때 operator[]로 삽입하지 않도록 주의
}

unordered_set<string> seen;
bool first = seen.insert("apple").second;
bool exists = seen.count("apple") != 0;
seen.erase("apple");
```

작은 정수 범위라면 배열로도 빈도를 셀 수 있다. 문자열 등 넓은 키 범위에는 해시가 편리하다. unordered 컨테이너의 순회 순서는 정렬 순서가 아니므로 출력 순서가 필요하면 별도 정렬한다. 문자열 해싱 비용은 문자열 길이의 영향도 받는다.

## 완료 기준

- [ ] set으로 중복을 없애도 되는지, 빈도를 보존해야 하는지 설명한다.
- [ ] find/count와 operator[]의 차이를 이해한다.
- [ ] 동명이인, 문자열 선행 0, 동률 정렬을 필요한 문제에서 검증한다.
- [ ] 컨테이너 순회 순서에 의존하지 않는다.
